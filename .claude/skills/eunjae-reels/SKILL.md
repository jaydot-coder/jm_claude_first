# 은재왔지 릴스 제작

도구는 `eunjae-reels/` 폴더에 있다(설치는 `eunjae-reels/README.md`, `setup.sh`). 사용자(곰키)는 한국어로 소통한다.

## 기본 규칙
- 자막 글씨체는 **Jua**(`eunjae-reels/fonts/Jua-Regular.ttf`), 흰색, 둥글고 귀여운 느낌. 사용자가 따로 말하지 않으면 항상 이것.
- 출력은 1080x1920, 30fps. 인스타 릴스 **세이프존**: 왼쪽 64, 오른쪽 120, 위 270, 아래 420(px). 제목·자막 모두 이 박스 안에 둔다. 자막 글자 크기는 80px 이상(현재 92px).
- 제목은 아기 눈 위로 올린다(얼굴 가리지 않게). 사용자가 "조금 더 위로"라고 하면 `make_reel2.py`의 `T + 107` 부분을 조정.
- 한 번 만들 때마다 한 컷(`guide_t guide.png`)으로 세이프존과 겹침을 눈으로 확인한 뒤 전체를 렌더링.

## 색(HDR) 유지 — 가장 중요한 함정
- 갤럭시/아이폰 원본은 보통 **HEVC 10비트, HLG(arib-std-b67), BT.2020**(Dolby Vision 포함일 수 있음). 먼저 `ffprobe`로 확인.
- 8비트 H.264로 다시 인코딩하면 HDR 정보가 사라져 폰이 SDR로 재생하고, **채도가 빠진 칙칙한 영상**이 된다(픽셀 값은 거의 같아도 그렇게 보임).
- 그래서 `make_reel2.py`는 10비트 HEVC(`hvc1`) + HLG/BT.2020 태그를 그대로 유지하고 소리는 `-c:a copy`로 복사한다. 원본 소리를 키우거나 바꾸지 않는다(사용자가 원하면 그때만).
- 글자색은 HLG **신호값을 그대로** 지정한다. sRGB→HLG 변환(`hlg()`)을 쓰면 흰색이 회색, 노랑이 탁하게 나온다(사용자 지적). 현재: 흰색 (255,255,255), 쨍한 노랑 (255,245,0), 외곽선 (45,30,15). 노랑은 G를 255 쪽으로 올려야 주황빛이 안 난다.
- 확인 방법: ffprobe 태그가 원본과 같은지, 자막 없는 영역 PSNR(약 53dB), 소리 스트림 md5 동일, HDR→SDR 톤매핑 미리보기.
- Dolby Vision 추가 정보는 유지되지 않는다(HLG 기본층만 유지).

## 음성 자막 정확도
- 아기·아빠 말투(노래 부르듯 늘어지는 말)는 한 모델만으로는 틀린다. **Whisper large-v3와 한국어 zipformer 결과를 교차 확인**하고, 사용자가 알려 주는 힌트(예: "초반엔 슬퍼요~ 화가난당~")로 교정한다.
- 확실하지 않은 낱말은 사용자에게 확인받는다. 자막은 말이 시작되기 약 0.05초 전에 나타나고, 최소 0.9초 유지.

## 의성어(소리) 자막 릴스
- `make_reel.py`: 소리 세기(SNR 기반)에 맞춰 글자가 커지고 떨리게 한다. 소리가 아주 작은 원본(-57LUFS)이라 +28dB 증폭이 들어 있으니, 원본 소리를 유지해야 하면 이 부분을 빼고 쓴다.
- HyperFrames 경로(`make_hf_index.py`)는 선택. 렌더에 로컬 Chromium 경로(`HYPERFRAMES_BROWSER_PATH`)가 필요했고 같은 영상 기준 PIL 방식보다 느렸다(약 5분).

## 아직 확인 안 된 것
- 실제 폰·인스타에서 재생한 결과는 확인하지 못했다. 업로드 후 HDR 처리 방식에 따라 글자가 다소 밝거나 어둡게 보일 수 있다.
