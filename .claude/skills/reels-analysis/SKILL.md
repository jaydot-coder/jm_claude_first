# 릴스 분석

## 원칙
- 영상을 실제로 본다. 대본만 읽고 판단하지 않는다(화면 캡처를 반드시 직접 본다).
- 대본·첫 문장·댓글 유도 문장은 요약하지 말고 원래 문장 그대로 인용한다.
- 확인 못 한 건 "확인 불가"라고 쓴다. 숫자를 지어내지 않는다.
- "훅이 강하다" 같은 말은 분석이 아니다. 몇 초에 무엇이 어떻게 나와서 그런지 쓴다.

## 1. 재료 뽑기 (링크마다, 작업 폴더의 reels/<영상ID>/ 에 저장)
- yt-dlp로 영상과 정보(조회수·좋아요·댓글 수·캡션·계정)를 받는다. 막히면 --cookies-from-browser chrome 으로 다시 시도.
- whisper-cli(모델 ~/.cache/whisper/ggml-large-v3-turbo-q5_0.bin, 한국어)로 [00:00] 형식 대본을 뽑는다.
- ffmpeg로 0~3초는 초당 4장, 전체는 2초마다 1장씩 캡처해 한 장짜리 모아보기 이미지로 만들고 직접 본다.
- ffmpeg scene 감지로 컷 수와 평균 컷 길이를 잰다.

## 2. 6가지로 뜯기 (각각 관찰 → 판정 → 내 계정에 옮길 점)
1. 대본: 구간표 — 몇 초 | 역할(훅/공감/본론/반전/마무리/댓글 유도) | 원래 문장 | 다음을 보게 만든 장치
2. 포맷: 말하는 얼굴/화면녹화/자막 중심/리스트 등, 촬영 난이도, 자막 스타일
3. 주제: 누구의 어떤 문제인가, 왜 지금인가
4. 스토리텔링 구조: 처음에 약속한 것과 마지막에 준 것, 끝까지 보게 만든 열린 고리
5. 훅: 첫 3초를 화면/소리/말 3가지로 나눠서. 첫 문장 원문, 방식(질문·숫자·반전·손해·비교·비밀 공개), 셋이 같은 약속을 하는지
6. 화면 구성: 인물 위치, 자막 위치·크기·색, 자료 화면, 몇 초마다 화면이 바뀌는지
+ 댓글 유도: 문장 원문, 몇 초에 나왔는지, 보상이 뭔지

## 3. 출력
한 줄 요약(터진 진짜 이유) → 지표 → 6가지 분석 → 재사용 틀(내용만 ___ 빈칸으로 바꾼 대본 뼈대, 문장 수·길이·리듬은 그대로) → 훔칠 것 3가지

## 4. 여러 개를 한꺼번에 받았을 때
- 링크마다 1~2단계를 돌리고, 결과를 작업 폴더의 reels/분석표.csv 에 한 줄씩 쌓는다(링크·계정·조회수·첫 문장·훅 방식·포맷·주제·길이·컷 수·댓글 유도 문장).
- 마지막에 공통 패턴 리포트: 반복되는 첫 문장 틀(원문 예시와 함께), 먹히는 포맷·화면 배치, 주제 트렌드, 조회수 상위와 하위의 차이, 아무도 안 한 빈자리. 항목마다 "몇 편 중 몇 편"으로 근거를 적는다.
